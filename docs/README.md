# OctoAcme Project Management Docs

Start here to learn how OctoAcme runs projects. OctoAcme uses a lightweight, collaborative model centered on clear ownership, iterative delivery, visible planning, regular communication, and continuous improvement.

## Process at a Glance

Work typically moves through **initiation → planning → execution → release → retrospective**, with risk and dependency tracking maintained throughout.

- **Initiation:** confirm the business need, identify stakeholders, define success metrics, and decide whether to proceed.
- **Planning:** build the backlog and release plan, prioritize and estimate, and agree on a Definition of Done.
- **Execution:** track work on the project board (Backlog, Ready, In Progress, In Review, QA, Done) using small, issue-linked pull requests.
- **Release:** pass CI and security scans, draft release notes, and have a rollback plan.
- **Retrospective & continuous improvement:** review after milestones and releases, and feed action items back into the backlog.
- **Risk management & communication:** keep a risk register reviewed weekly, and use standups, weekly syncs, milestone reviews, and clear escalation paths.

## Core Roles

- **Project Manager:** coordinates delivery, schedules, risks, and communications.
- **Product Manager / Product Lead:** owns outcomes, prioritization, and success measurement.
- **Developers:** implement and test the work.
- **QA:** validates quality and acceptance criteria.
- **Stakeholders:** provide input and approvals.
